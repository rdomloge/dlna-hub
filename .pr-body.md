## Problem

Changing locations quickly (tapping into one folder, then into another) fills the BrowsePage with rows from two different locations mixed together.

Additionally, after repeated navigation to the same folder (e.g., Root > Video > TV → Root > Video → Root > Video > TV), the date-sorted view stops showing dates — items render in title (A-Z) order.

## Root cause

### Bug 1: Stale-response row mix
The `fetchItems` stale-response guard in `BrowsePage.tsx` was **recency-only**: it checked `requestId !== latestRequestRef.current` — "am I the newest request?" — but never verified that the request's **target identity** (folder + query) still matched the current browse state.

### Bug 2: Date-stream cache not invalidated on navigation
The backend's `containerDateCache` is shared across all folders. When the user navigates Root > Video > TV, the TV subtree's containers are crawled and cached. When the user navigates away to Root > Video and then back to TV, the cache still marks TV's containers as fresh (same SystemUpdateID), so the SSE date stream emits only `allDone` without any date events. The frontend shows items in default title order.

## Fix

### 1. Identity-aware guard (root-cause fix)
Each `fetchItems` call now captures its `(folderId, query)` identity into `activeRequestRef`. Before any state write (success, error, finally), it verifies the response still matches the current browse identity. Stale-identity responses are dropped — no write.

### 2. Clear pending debounce timer
`handleNavigate`, `handleBreadcrumbClick`, `handleSortChange`, and the search-clear button now call `clearTimeout(searchTimeoutRef.current)` before navigating.

### 3. AbortController for in-flight request cancellation
Each `fetchItems` creates a new `AbortController` and aborts any previous one. Navigation/sort/unmount also abort.

### 4. Clear container date cache before each SSE date stream
`runDateStream()` now removes the server's `containerDateCache` at the start. This ensures the stream always re-crawls and emits date events, fixing the bug where repeated navigation causes date-sort to silently stop working.
